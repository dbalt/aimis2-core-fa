# Proposal: Мотивационная корректировка

## Why (причина)

Метрики факторного анализа показывают отклонения факта от плана, но не отражают внешний
аддитивный фактор — мотивационную корректировку. Этот фактор:

- Загружается из БД отдельным запросом (не входит в иерархию показателей).
- Влияет на итоговые значения плана и факта, но не участвует в факторной декомпозиции.
- Должен быть виден в JSON-результате и поясняться в LLM-саммари.

Без поддержки мотивационной корректировки итоговый отчёт не отражает полную картину
отклонений.

## What Changes (изменения)

1. **Новый dataclass `MotivCorrectionMetadata`** — описывает, откуда брать данные корректировки (поле `query` для WHERE-фильтрации).
2. **Новое опциональное поле `motiv_correction`** в `DeviationCalcMetadata` — подхватывается без изменения поведения по умолчанию.
3. **Новая функция `get_motiv_correction_data()`** — загружает один ряд `DataRow` из БД параллельно с расчётом отклонений по иерархиям.
4. **Модификация `collect_for_summary()`** — прибавляет значения корректировки к `amounts` корневого узла, добавляет ключ `"motiv_correction"` в JSON.
5. **Модификация `calculate_and_summarize_deviation()`** — запускает `get_motiv_correction_data()` параллельно с `calculate_deviations()` через единый `asyncio.TaskGroup`.
6. **Модификация `summarize.py`** — добавляет детерминированный блок пояснения в текстовый отчёт, если корректировка ненулевая.

## Expected Outcome

- При установленном `motiv_correction` итоговый JSON содержит ключ с цифрами плана/факта/отклонения корректировки, а amounts корня скорректированы.
- При отсутствии `motiv_correction` или пустых данных поведение системы не меняется.
- В тексте LLM-саммари появляется блок «Данные до корректировки» с вычисленными значениями `plan_before` и `fact_before`.

## Capabilities

Новая capability: `motiv-correction` — поддержка мотивационной корректировки в модуле факторного анализа.
