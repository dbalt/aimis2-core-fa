# Delta Spec: fa-summary-prompt-accuracy

## Purpose

Требования к промптам саммаризации ФА: числа — только цитаты display-строк, запрет выдуманных драйверов и причинно-следственных оборотов у листовых узлов, обязательная формулировка вклада маржи, согласованность правил — чтобы LLM не сочиняла данные, отсутствующие во входе.

## ADDED Requirements

### Requirement: Числа в отчёте — только цитаты входных display-строк

Промпты саммаризации SHALL требовать, чтобы каждое число в сгенерированном тексте было точной цитатой display-строки, предоставленной во входных данных. Выполнение арифметических операций над числами (деление, умножение, выбор масштаба, перегруппировка разрядов) в промптах SHALL быть запрещено.

#### Scenario: Число из входа процитировано дословно

- **WHEN** LLM генерирует текст по данным, содержащим display-строку `"11 047,2 млн руб."`
- **THEN** в тексте встречается именно `"11 047,2 млн руб."`, а не иное представление того же числа

#### Scenario: Число, отсутствующее во входе, не появляется

- **WHEN** во входных данных нет числа, которое LLM включила в черновик текста
- **THEN** такой вывод классифицируется как ошибка `INVENTED_NUMBER` валидатором-оракулом (см. capability fa-summary-prompt-ab-testing) и не считается допустимым результатом

### Requirement: Запрет выдуманных драйверов у листовых узлов

Промпты SHALL запрещать указывать «Главный драйвер», вложенную детализацию и причинно-следственные обороты («за счёт», «вследствие», «благодаря») для факторов, у которых во входных данных отсутствуют дочерние узлы. Формулировка «Главный драйвер» SHALL использоваться только когда источник драйвера — имя существующего дочернего узла из входа.

#### Scenario: Листовой фактор без драйвера

- **WHEN** фактор «Операционный доход до резервов» во входных данных не имеет дочерних узлов
- **THEN** в выводе для него нет ни строки «Главный драйвер», ни вложенных факторов, ни чисел, не входящих во вход

#### Scenario: Драйвер из имени ребёнка допустим

- **WHEN** у фактора во входных данных есть ровно один дочерний узел, дающий ≥90% вклада родителя
- **THEN** допустима формулировка «Главный драйвер — <имя ребёнка> (<его display-строка>)»

#### Scenario: Переупаковка план/факт в драйвер запрещена

- **WHEN** у узла есть значения plan/fact, но нет дочерних узлов
- **THEN** не допускается представлять план/факт узла как «драйвер» его отклонения (класс ошибки `REPACKED_PLAN_FACT`)

### Requirement: Согласованность правил отбора и полноты

Промпты SHALL быть свободны от противоречий между «полнотой вывода» и «запретом упоминания пустых деревьев»: количество секций по аналитическим осям MAY быть меньше количества осей, если у дерева нет дочерних узлов и значимого отклонения. Секция для дерева без дочерних узлов и без отклонения SHALL не создаваться, и это SHALL не считаться нарушением полноты.

#### Scenario: Ось без детей не порождает секцию и не провоцирует выдумку

- **WHEN** во входных данных есть аналитическая ось (дерево) без дочерних узлов и без значимого отклонения
- **THEN** промпт не требует выводить секцию по этой оси, и LLM не должна создавать для неё факторов

### Requirement: Формулировка вклада маржи (ratio)

Для ratio-метрик промпт SHALL требовать формулировку вклада потомка в виде «отклонение маржи составило {X п.п.}, что оказало влияние на верхнеуровневый показатель в {Y руб.}», где {X п.п.} и {Y руб.} — готовые строки из входных данных.

#### Scenario: Вклад потомка ratio-метрики сформулирован по шаблону

- **WHEN** генерируется отчёт для ratio-метрики и во входе есть пара строк `"-26,4 п.п."` и её рублёвый эквивалент
- **THEN** вклад потомка описан фразой вида «отклонение маржи составило 26,4 п.п., что оказало влияние на верхнеуровневый показатель в …», с числами из входа

### Requirement: Маркеры и лексика

Промпты SHALL требовать: маркер 🔴 перед каждым отрицательным вкладом, ❇️ перед каждым положительным; знак числа согласован с маркером; другие эмодзи (включая 🟢) запрещены; слова динамики («рост», «снижение», «падение», «увеличение», «прирост» и производные) запрещены; технические термины входа («top_factors», «impact_to_top_lvl», «разрез») запрещены в выводе.

#### Scenario: Маркер соответствует знаку

- **WHEN** в тексте встречается фактор с отрицательным вкладом
- **THEN** перед ним стоит 🔴 и число с минусом; вариант 🟢 недопустим

#### Scenario: Динамика отсутствует

- **WHEN** в тексте описываются факторы отклонения
- **THEN** слова «рост», «снижение», «увеличение» и производные отсутствуют; используются статичные формулировки с маркерами

### Requirement: Гигиена промптов

Тексты промптов SHALL не содержать символов и языков, не относящихся к языку промпта (например, китайских иероглифов в русском тексте), и SHALL не содержать взаимно противоречащих инструкций об одной операции.

#### Scenario: Промпты содержат только ожидаемые алфавиты

- **WHEN** выполняется проверка файлов промптов
- **THEN** в текстах промптов отсутствуют символы CJK и иные посторонние алфавиты

#### Scenario: Одна операция — одна инструкция

- **WHEN** промпт описывает форматирование чисел ratio-метрик
- **THEN** инструкции «умножай на 100» и «не умножай на 100» не противоречат друг другу: область применения каждой задана однозначно (процентные поля vs абсолютные величины)
