# Proposal: AIMIS-2173 — точность саммари факторного анализа (промпты + display-форматирование)

## Why

GigaChat допускает в саммари ФА (раздел «Ключевые факторы») выдуманные данные: сочинённые драйверы и числа для узлов, у которых нет детализации в JSON («Информации по детализации Операционного дохода до резервов у него не было, однако он выдумал какие-то факторы по ней»). Также теряет разряды при форматировании («29213 млн» вместо «29213553 млн (29213 млрд)», «1 105 млн» вместо «11 047,2 млн») и некорректно формулирует вклад маржи. Причина — промпты поручают LLM арифметику (деление на scale, ×100, выбор масштаба, группировка тысяч) и свободное заполнение шаблона «Главный драйвер» без данных для него.

## What Changes

**Принцип: числа в отчёте пишет только форматтер (код), LLM только цитирует готовые строки (уровень A). Runtime-валидатор в прод не вводится.**

- **Форматтер display-строк** — новый детерминированный модуль: для каждого числа входного дерева вычисляет готовую строку («11 047,2 млн руб.», «−21,7 п.п.», пары «п.п. + рублёвый эквивалент» для ratio), маркер по знаку, флаг значимости. Промпты получают данные с готовыми строками; LLM запрещено вычислять и выдумывать числа.
- **Ревизия промптов** (`summarize_prompts.py`):
  - запрет «Главного драйвера» и причинно-следственных оборотов у узлов без детей; запрет переупаковки plan/fact узла в «драйвер»;
  - устранение конфликта правил «каждая ось обязательна в выводе» vs «не упоминай пустое дерево»;
  - обязательная формулировка маржи (ветка 4): «отклонение маржи составило {X п.п.}, что оказало влияние на верхнеуровневый показатель в {Y руб.}»;
  - строго ❇️/🔴 (без 🟢), запрет слов динамики;
  - числа в ответе — только точные цитаты display-строк из входа;
  - удаление китайских иероглифов 执行 из `_KEY_FACTORS_BRANCH_2`.
- **A/B-харнесс** (adhoc, не прод): 10 независимых последовательных прогонов суммаризации на старом промпте и 10 на новом с валидатором-оракулом (тестовый код, не прод); метрики по классам ошибок; итерации промпта до 0 ошибок на всех прогонах.
- **Замена дефолта модели**: `GigaChat-2-Max` → `GigaChat-3-Ultra` для `model_details`/`model_table` в 4 местах этого репо. SDK aimis-sdk и конфиг KeyDB не затрагиваются.

## Capabilities

### New Capabilities

- `fa-value-display-formatting`: детерминированное форматирование чисел ФА в готовые display-строки (масштаб, группировка, разделители, маркеры, флаги значимости, п.п.+рубли для ratio) для передачи в промпты саммаризации.
- `fa-summary-prompt-accuracy`: требования к промптам саммаризации — цитирование вместо вычислений, запрет выдуманных драйверов у листьев, обязательная формулировка маржи, согласованность правил.
- `fa-summary-prompt-ab-testing`: харнесс последовательных A/B-прогонов (10×старый vs 10×новый промпт) с валидатором-оракулом и метриками ошибок.

### Modified Capabilities

(нет — существующие спеки `csid-transport`, `drill-negative-filtering` не затрагиваются)

## Non-goals

- Runtime-валидатор в проде — только тестовый оракул в харнессе.
- Уровень B (LLM возвращает структуру, числа подставляет рендерер) — эскалация только если уровень A не достигнет 0 ошибок.
- Tool-calling/агентные тулзы для вычислений.
- Изменения SDK aimis-sdk (`DEFAULT_GIGA_MODEL`), конфигов KeyDB (`configs.fa2026.models.*`), `table_renderer.py` (уже детерминирован), протокола `fa2026`, кэширования DataMgmt.
- Ретраи/очереди прокси GigaChat — отдельная инфраструктурная задача.

## Impact

- **Код**: `src/libfa2/fa_impl/` — новый модуль форматтера; `summarize_prompts.py` — ревизия промптов (4 ветки × саммари/факторы + motiv), legacy-версии сохраняются для харнесса; `summarize.py` — подключение форматтера, параметризация промптов (для A/B), дефолты моделей; `all_together.py`, `fa_server.py`, `run__fa_server.py` — дефолты моделей; `src/adhoc/` — харнесс на базе `adhoc__make_summaries_from_jsons.py`.
- **Тесты**: unit-тесты форматтера (вкл. red-кейс «29213553 млн»); red/green-фикстуры валидатора на 5 SQL-примерах из `t_aimis__fa__results`; прогон харнесса требует доступа к GigaChat через прокси и данных от заказчика (запрашиваются на этапе имплементации).
- **Инфраструктурные ограничения**: прокси GigaChat — 1 соединение, `maxRetries=0` → прогоны строго последовательные; внутри прогона сохраняется штатная параллельность (3 запроса TaskGroup).
- **Риски совместимости**: нет — контракт `GET_DEVIATION_SUMMARY` не меняется, меняется только содержимое `summary` (текст) и дефолт модели.
