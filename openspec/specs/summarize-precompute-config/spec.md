# summarize-precompute-config Specification

## Purpose
Даёт возможность через конфиг сервиса выбирать для каждого предвычисления саммаризации (числа, маркеры, отбор факторов, ограничения имён), готовит ли его код или отдаёт LLM, и настраивать порог отбора факторов; дефолт — всё считается кодом (текущее поведение).

## Requirements

### Requirement: Конфиг с ручкой code|llm на каждый параметр предвычисления
Система SHALL поддерживать вложенный конфиг `configs.fa2026.summarize.precompute`, в котором для каждого предвычисляемого параметра задается режим: `code` (значение готовит код) или `llm` (значение вычисляет LLM по правилам legacy-промптов). Параметры: форматирование чисел (`numbers`), маркеры (`markers`), отбор значимых факторов (`selection`), белый список имён (`names.allowed`), ограничения «Главного драйвера» (`names.children`). Если конфиг или его часть отсутствует, система SHALL использовать дефолт: все параметры `code`.

#### Scenario: Конфиг отсутствует — поведение не меняется
- **WHEN** ключ `configs.fa2026.summarize.precompute` в KeyDB не задан
- **THEN** все параметры предвычисляются кодом (display-строки, маркеры, значимость, имена) — отчёт идентичен поведению до этого изменения

#### Scenario: Параметр в режиме llm
- **WHEN** для параметра задано `mode: "llm"`
- **THEN** код не генерирует для него готовое значение в данных, а промпт инструктирует LLM вычислить его самостоятельно по правилу из legacy-промпта

### Requirement: Настраиваемый порог отбора факторов
Порог отбора значимых факторов (доля от максимального |вклада| среди соседних узлов) SHALL быть настраиваемым в конфиге внутри `selection` (`threshold`, дефолт 0.30) вместе с правилом похожести соседних факторов (`similarity`, дефолт 0.15). Корневой узел SHALL всегда считаться значимым независимо от порога.

#### Scenario: Порог переопределен
- **WHEN** задано `selection: {mode: "code", threshold: 0.5}`
- **THEN** код помечает значимыми только факторы с |вкладом| >= 50% максимума среди соседей

#### Scenario: Порог передается в LLM-режим
- **WHEN** задано `selection: {mode: "llm", threshold: 0.4}`
- **THEN** промпт содержит правило отбора с числом 40% (LLM отбирает сама)

### Requirement: numbers=llm форсирует llm для остальных параметров
Режим `numbers: "llm"` SHALL форсировать режим `llm` для `markers`, `selection` и `names`: без готовых display-строк остальным код-правилам не на что ссылаться.

#### Scenario: Смешанный конфиг с numbers=llm
- **WHEN** задано `numbers: "llm"` при остальных `code`
- **THEN** все параметры работают в режиме `llm` (поведение соответствует legacy-промптам)

### Requirement: Мотив-блок и margin-пара следуют за numbers
Форматирование чисел мотивационного блока и пары «X п.п. / Y руб.» для ratio SHALL управляться единой ручкой `numbers` (отдельных ручек нет: эти числа неразделимы с остальными display-строками).

#### Scenario: numbers=llm затрагивает мотив-блок
- **WHEN** задано `numbers: "llm"` и в данных есть мотивационная корректировка
- **THEN** числа мотив-блока не форматируются кодом; LLM форматирует их по общему правилу чисел

### Requirement: Промпт собирается по конфигу
Система SHALL собирать тексты промптов в зависимости от режимов конфига: для `code`-параметров — инструкции цитировать готовые значения, для `llm`-параметров — инструкции вычислять самостоятельно (источник формулировок — legacy-промпты) с подстановкой порогов из конфига.

#### Scenario: Все параметры code
- **WHEN** все ручки в режиме `code`
- **THEN** промпты содержат текущие правила (числа — только точные цитаты display-строк, отбор — только помеченные значимыми)

#### Scenario: Отбор в режиме llm
- **WHEN** `selection` в режиме `llm`
- **THEN** в промпте нет ссылки на флаг значимости, вместо него — правило «включай факторы с |вкладом| >= {{threshold}} максимума»

### Requirement: Валидация конфига на старте (fail-fast)
Система SHALL валидировать конфиг при старте сервера: значения режимов только `code`/`llm`, пороги — числа в допустимых диапазонах (0 < threshold, 0 < similarity < 1), неизвестные ключи запрещены. При невалидном конфиге сервер SHALL завершить старт с ошибкой, указывающей имя невалидного ключа и ожидаемое значение.

#### Scenario: Невалидное значение режима
- **WHEN** в конфиге задано `numbers: "auto"` (недопустимое значение)
- **THEN** старт сервера завершается ошибкой с указанием ключа `numbers` и допустимых значений `code|llm`

#### Scenario: Порог вне диапазона
- **WHEN** задано `selection: {threshold: -0.1}`
- **THEN** старт сервера завершается ошибкой с указанием ключа `selection.threshold` и допустимого диапазона
