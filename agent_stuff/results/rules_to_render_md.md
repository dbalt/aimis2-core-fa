# Правила рендеринга markdown-отчётов факторного анализа в HTML

> Инструкция-референс. Описывает воспроизводимый способ рендерить `.md`-отчёты
> факторного анализа (папка `src/adhoc/mds/`) в статичный HTML. Применялась в
> задаче 32 ([генератор](../../src/adhoc/make_html_from_mds.py),
> [отчёт по задаче](../reports/32_make_one_html_from_many_report.md)).
>
> Если нужно собрать HTML из другой партии отчётов (другая дата/папка) — следуйте
> правилам ниже и используйте эталонный код из последнего раздела.

---

## 0. Что важно знать про исходный контент

`.md`-отчёты ФА имеют фиксированный набор особенностей, и под каждую есть своё
правило ниже:

| Особенность | Пример | Чем обрабатывается |
|---|---|---|
| GFM-таблицы с выравниванием | `\|---:\|---:\|` | расширение `tables` |
| Экранированный пайп **внутри** ячейки | `Расчетно-кассовое обслуживание \| ММБ` | расширение `tables` (встроено) |
| Эмодзи-маркеры позитив/негатив | 🔴 🟢 | проходят как UTF-8 без обработки |
| HTML-сущности для отступа | `&emsp;`, `&emsp;&emsp;`, `№` | проходят как текст без обработки |
| Жирный/курсив | `**текст**`, `*↳ по ГОСБ*` | базовый парсер |
| Вложенные списки с отступом **2 пробела** | `- a` → `  - b` → `    - c` | **`tab_length=2`** (правило 2) |
| Список **без пустой строки** после абзаца | `**По блокам:**\n- item` | **`normalize_lists()`** (правило 3) |

---

## 1. Инструмент — Python-Markdown

Используется библиотека `markdown` (в venv `foo` её изначально нет — ставится из
внутреннего зеркала):

```bash
source /Users/baltakov-df/venv/foo/bin/activate
pip install markdown   # markdown==3.10.2
```

Свой ручной парсер НЕ подходит — GFM-таблицы (экранированные `\|`, выравнивание
`:`) слишком капризны.

## 2. Правила конфигурации

### Правило 1. Набор расширений: `tables`, `fenced_code`, `attr_list`

```python
MD_EXTENSIONS = ["tables", "fenced_code", "attr_list"]
```

- `tables` — **обязательно**: весь контент ФА построен на GFM-таблицах. Заодно
  корректно обрабатывает `\|` как литерал `|` внутри ячейки (а не как разделитель
  колонок).
- `fenced_code`, `attr_list` — на всякий случай (код-блоков в текущих данных нет,
  но безопасно).
- **НЕ использовать `sane_lists`.** Это расширение: (а) требует пустую строку
  перед списком — усугубляет проблему из правила 3; (б) по документации не
  поддерживает вложенные списки. Без него стандартный парсер нативно строит
  вложенность.

### Правило 2. `tab_length=2` — для вложенных списков

В исходных `.md` вложенные пункты имеют отступ **2 пробела** (а не 4). С дефолтным
`tab_length=4` такие подпункты **схлопнутся в плоский список** верхнего уровня.

```python
markdown.markdown(text, extensions=MD_EXTENSIONS, tab_length=2)
```

### Правило 3. `normalize_lists()` — КЛЮЧЕВОЕ правило

**Python-Markdown не позволяет списку прервать абзац.** Строка `- item`
распознаётся как пункт списка **только** если перед ней есть пустая строка.
Иначе весь блок (включая `-`) проваливается в предшествующий абзац, и маркеры
остаются literal-текстом:

```markdown
**По бизнес-блокам:**
- 🔴 ММБ — **−137,0 млн руб.**     ← НЕТ пустой строки → '- 🔴 ММБ' = literal-текст
```

Это поведение самого парсера, расширениями **не отключается**. В отчётах ФА это
правило нарушено в ~60% файлов (48 из 80 на дату `2026-04-30`). Менять данные
нельзя (они из БД), поэтому markdown **нормализуется перед рендером**: вставляется
пустая строка перед списком, идущим сразу после обычной строки.

Требования к нормализатору:
- не трогать уже разделённые пустой строкой блоки;
- **не ломать вложенность** — между пунктами одного списка пустые строки не
  добавляются (проверяем, что предыдущая строка — не пункт списка);
- игнорировать содержимое fenced code-блоков.

> **Почему именно эта последовательность шагов:** правило 2 даёт вложенность,
> правило 3 — корректное распознавание списков вообще. Вместе они поднимают
> `<li>` с 402 → 938 и сводят число файлов со сломанными списками с 48 до 0.

## 3. Эталонный код (копировать целиком)

```python
import re
import markdown

MD_EXTENSIONS = ["tables", "fenced_code", "attr_list"]
MD_TAB_LENGTH = 2

_ULIST_RE = re.compile(r"^[ \t]*([-*+])[ \t]+\S")
_OLIST_RE = re.compile(r"^[ \t]*\d{1,9}[.)][ \t]+\S")
_FENCE_MARKERS = ("```", "~~~")


def _is_list_item(line: str) -> bool:
    return bool(_ULIST_RE.match(line) or _OLIST_RE.match(line))


def normalize_lists(md_text: str) -> str:
    """Вставить пустую строку перед списком, идущим сразу после обычного текста.

    Python-Markdown не даёт списку прервать абзац: `- item` становится списком
    только при пустой строке перед ним, иначе проваливается literal-текстом в
    абзац. Между пунктами одного списка пустые строки НЕ добавляются.
    """
    out: list[str] = []
    in_fence = False
    fence_marker = ""
    for line in md_text.split("\n"):
        stripped = line.lstrip()
        if stripped[:3] in _FENCE_MARKERS:
            if not in_fence:
                in_fence = True
                fence_marker = stripped[:3]
            elif stripped.startswith(fence_marker):
                in_fence = False
        if (
            not in_fence
            and out
            and _is_list_item(line)
            and out[-1].strip() != ""
            and not _is_list_item(out[-1])
        ):
            out.append("")  # разделить абзац и список пустой строкой
        out.append(line)
    return "\n".join(out)


def render_md_to_html(md_text: str) -> str:
    """Сконвертировать markdown-отчёт ФА в HTML-фрагмент."""
    md_text = normalize_lists(md_text)
    return markdown.markdown(
        md_text,
        extensions=MD_EXTENSIONS,
        output_format="html",
        tab_length=MD_TAB_LENGTH,
    )
```

## 4. Чек-лист проверки результата

После сборки HTML прогнать эти проверки (все должны быть зелёными):

| Проверка | Как проверить | Ожидание |
|---|---|---|
| Нет literal-списков | `re.search(r'<p>[^<]*\n[-*+] ', html)` или `</strong>\n- [🔴🟢]` | не найдено |
| Таблицы целы | `html.count('<table>')` | по числу отчётов |
| Вложенность работает | визуально: подпункты вложены в `<ul><li>...<ul>` | есть вложенные `<ul>` |
| Пайп в ячейке — литерал | поиск ` \| ` внутри `<td>` | есть, ячейка не разъехалась |
| Эмодзи/сущности на месте | `🔴`/`🟢`, `&emsp;`, `№` | присутствуют |
| Остатки сырой разметки | `html.count('**')` | 0 |
| Баланс тегов | `html.parser.HTMLParser` | 0 незакрытых, 0 ошибок |

**Эталонные цифры** для партии `2026-04-30` (80 файлов): `<ul>` = 470,
`<li>` = 938, `<table>` = 80.

## 5. Чего делать НЕ надо (найденные тупики)

- ❌ `sane_lists` — ломает распознавание списков без пустой строки и мешает
  вложенности.
- ❌ Дефолтный `tab_length=4` — теряется вложенность подпунктов.
- ❌ Рассчитывать, что список сам прервёт абзац — в Python-Markdown это не так
  (в отличие от CommonMark/GitHub). Нужен препроцессинг `normalize_lists`.
- ❌ Пытаться «донастроить расширениями» правило прерывания абзаца списком —
  такого расширения нет, правится только препроцессингом исходного текста.
- ❌ Экранировать/замещать `\|`, `&emsp;`, эмодзи вручную — всё корректно
  обрабатывается/проходит как есть, ручное вмешательство только навредит.
