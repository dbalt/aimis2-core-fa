# Требования к структуре таблицы базы данных для факторного анализа

## Краткое описание структуры метаданных

### Метаданные иерархии показателей

Метаданные иерархии описывают древовидную структуру финансовых показателей, где каждый узел может быть:
- **Листом** — показатель, получаемый напрямую из БД
- **Составным узлом** — показатель, рассчитываемый из дочерних компонентов

**Типы составных узлов:**
- `sum` — сумма дочерних компонентов
- `multi` — произведение множителя (rate) на базу (base)
- `ratio` — отношение числителя к знаменателю (только для корневого показателя)

**Пример метаданных иерархии:**
```json
{
  "id": 10,
  "code": "NII",
  "name": "Чистый процентный доход",
  "parent": 1,
  "type": "sum"
},
{
  "id": 101,
  "code": "INT_INC",
  "name": "Процентный доход",
  "parent": 10,
  "type": "multi",
  "query": {
    "metric": "interest_income"
  }
}
```

Для собираемых из БД показателей указывается свойство `query` с параметрами фильтрации. Для определения конкретного показателя в таблице БД используется поле `metric` из свойства `query` (__в данном примере__).


### Метаданные разложения по аналитическим разрезам

Метаданные описывают алгоритмы разворота значений показателей по аналитическим измерениям:
- Сегмент (segment)
- Геоструктура (geo_structure)
- Продукт (product)


Каждый алгоритм определяет порядок последовательной детализации данных. Таблица хранит только самые детализированные данные, а тоталы и сабтоталы рассчитываются программно.

**Пример метаданных аналитических разрезов:**
```json
{
  "algorithms": [
    {
      "id": 1,
      "drill_order": [
        ["segment"],
        ["geo_structure"],
        ["product"]
      ]
    }
  ],
  "dimensions": [
    {
      "code": "segment",
      "name": "Сегмент",
      "column": "segment"
    },
    {
      "code": "geo_structure",
      "name": "Геоструктура",
      "column": "geo_structure"
    },
    {
      "code": "product",
      "name": "Продукт",
      "column": "product"
    }
  ]
}
```

## Требования к таблице

### Структура таблицы `fa_indicator_data`

В контексте обеспечения данными в рамках описанного примера, нужна таблица такой структуры:

| Столбец | Тип данных | Обязательный | Описание |
|---------|-----------|--------------|----------|
| `metric` | varchar(50) | Да | Тип метрики (соответствует полю `metric` в свойстве `query` метаданных иерархии) |
| `rep_dt` | date | Да | Отчетная дата |
| `val_plan` | decimal(18, 6) | Да | Значение плана |
| `val_fact` | decimal(18, 6) | Да | Значение факта |
| `segment` | varchar(50) | Да | Идентификатор сегмента |
| `geo_structure` | varchar(50) | Да | Идентификатор геоструктуры |
| `product` | varchar(50) | Да | Идентификатор продукта |

### Пояснения к данным

- Таблица содержит только самые детализированные записи (сегмент + геоструктура + продукт)
- Все столбцы имеют заполненные значения, отсутствуют тоталы и сабтоталы
- Для факторного анализа используются агрегации на лету:

**Общий итог (рассчитывается программно):**
- План: 1000.00 (сумма всех `val_plan`)
- Факт: 900.00 (сумма всех `val_fact`)
- Отклонение: -100.00

**Разложение по сегментам (рассчитывается программно):**
- UL (Юридические лица): план 600.00 → факт 650.00 (отклонение +50.00) ✓
- FL (Физические лица): план 300.00 → факт 200.00 (отклонение -100.00) ✗
- OTHER (Прочие): план 100.00 → факт 50.00 (отклонение -50.00) ✗

### Примеры запросов для разных уровней детализации

**Уровень 0: Общий итог (агрегация)**
```sql
SELECT metric, rep_dt,
       SUM(val_plan) as plan,
       SUM(val_fact) as fact,
       SUM(val_fact) - SUM(val_plan) as deviation
FROM fa_indicator_data
WHERE metric = 'commission_income_total'
  AND rep_dt = '2026-04-01'
GROUP BY metric, rep_dt;
```

**Уровень 1: По сегментам (агрегация)**
```sql
SELECT segment,
       SUM(val_plan) as plan,
       SUM(val_fact) as fact,
       SUM(val_fact) - SUM(val_plan) as deviation
FROM fa_indicator_data
WHERE metric = 'commission_income_total'
  AND rep_dt = '2026-04-01'
GROUP BY segment;
```

**Уровень 2: По геоструктурам для конкретного сегмента (агрегация)**
```sql
SELECT geo_structure,
       SUM(val_plan) as plan,
       SUM(val_fact) as fact,
       SUM(val_fact) - SUM(val_plan) as deviation
FROM fa_indicator_data
WHERE metric = 'commission_income_total'
  AND rep_dt = '2026-04-01'
  AND segment = 'FL'
GROUP BY geo_structure;
```

## Дополнительные требования

### Хранение только детализированных данных

- Таблица хранит только самые детализированные данные
- Тоталы и сабтоталы по аналитическим разрезам рассчитываются программно с помощью агрегаций (GROUP BY)
- Отсутствуют записи с обобщенными значениями разрезов
