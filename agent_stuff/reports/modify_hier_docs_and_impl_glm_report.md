# Отчет о проделанной работе: Интеграция метаданных разложения по аналитическим разрезам в иерархию показателей

**Дата:** 2026-04-17
**Задача:** Изменение концепции метаданных разложения по аналитическим разрезам с независимой сущности на отдельное свойство узла иерархии

---

## Обзор изменений

Концепция метаданных разложения по аналитическим разрезам изменена:
- **Ранее:** Метаданные были независимой сущностью, привязанной ко всей иерархии
- **Теперь:** Метаданные являются отдельным опциональным свойством каждого узла иерархии показателей

Это позволяет:
- Разным узлам одной иерархии иметь разные метаданные разложения
- Некоторым узлам не иметь метаданных разложения вообще
- Гибко управлять способом детализации для каждого конкретного показателя

## Технические решения

### Циклические импорты

Для избежания циклических импортов между модулями `hier_metadata` и `analyt_struct_metadata` используется подход с `TYPE_CHECKING`:

```python
from typing import TYPE_CHECKING

if TYPE_CHECKING:
    from libfa2.analyt_struct_metadata import AnalyticalStructureMetadata
```

Параметр `analyt_metadata` объявлен как строковый тип для type hints, что позволяет импортировать класс только во время проверки типов, а не во время выполнения.

### Сериализация AnalyticalStructureMetadata

Поскольку класс `AnalyticalStructureMetadata` не имеет метода `to_dict()`, для преобразования используется комбинация методов `to_json()` и `json.loads()`:

```python
result["analyt_metadata"] = json.loads(self.analyt_metadata.to_json())
```

Это корректно обрабатывает структуру с ключами `fa_impl` и `dimensions`.

## Примеры использования

### Создание узла с метаданными разложения

```python
from libfa2.hier_metadata import MetricNode, MetricType
from libfa2.analyt_struct_metadata import (
    AnalyticalStructureMetadata,
    Algorithm,
    Dimension,
)

# Создаем метаданные разложения
analyt_metadata = AnalyticalStructureMetadata()
analyt_metadata.add_dimension(Dimension(
    code="segment",
    name="Сегмент",
    column="segment_id"
))
analyt_metadata.add_dimension(Dimension(
    code="geo_structure",
    name="Геоструктура",
    column="geo_structure_id"
))
analyt_metadata.add_algorithm(Algorithm(
    id=1,
    drill_order=[["segment"], ["geo_structure"]]
))

# Создаем узел с метаданными
node = MetricNode(
    id=100,
    code="NII",
    name="Чистый процентный доход",
    type=MetricType.SUM,
    analyt_metadata=analyt_metadata
)
```

### Сериализация в JSON

```python
# Получаем JSON представление
json_dict = node.to_json()
# Результат:
# {
#     "id": 100,
#     "code": "NII",
#     "name": "Чистый процентный доход",
#     "type": "sum",
#     "analyt_metadata": {
#         "fa_impl": [{"id": 1, "drill_order": [["segment"], ["geo_structure"]]}],
#         "dimensions": [...]
#     }
# }
```

### Десериализация из JSON

```python
import json
json_str = '''
{
    "id": 100,
    "code": "NII",
    "name": "ЧПД",
    "type": "sum",
    "analyt_metadata": {
        "fa_impl": [{"id": 1, "drill_order": [["segment"]]}],
        "dimensions": [{"code": "segment", "name": "Сегмент", "column": "segment_id"}]
    }
}
'''
data = json.loads(json_str)
node = MetricNode.from_dict(data)
# node.analyt_metadata содержит корректно десериализованные метаданные
```

## Рекомендации по использованию

### Для каких типов показателей имеет смысл назначать analyt_metadata

| Тип показателя | Рекомендация | Причина |
|----------------|---------------|----------|
| `sum` | Рекомендуется | Значение вычисляется как сумма, детализация по аналитическим разрезам логична |
| `ratio` | Рекомендуется | Аналогично sum, детализация помогает понять вклад компонентов |
| `multi` | Не рекомендуется | Детализация по аналитическим разрезам выполняется на верхнем уровне, компоненты-множители рассчитываются через метод цепных подстановок |
| Листовой узел (type=None) | Не рекомендуется | Данные получаются напрямую из БД, дальнейшее разложение невозможно |

### Примеры конфигураций

1. **Полная детализация для всех узлов:**
   - Корень: детализация по 3 уровням (сегмент → геоструктура → продукт)
   - Потомки: наследуют или имеют свои варианты детализации

2. **Избирательная детализация:**
   - Показатель "Комиссионный доход": полная детализация
   - Показатель "Процентный доход": детализация только по сегменту
   - Показатель "Резервы": без детализации

3. **Без детализации:**
   - Показатели типа `multi` и листовые узлы не имеют `analyt_metadata`
