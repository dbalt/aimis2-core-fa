# Отчет: Генерация описания метаданных иерархии показателей

## Дата

2026-04-16

## Задача

Сгенерировать описание структуры хранения метаданных об иерархии показателей в формате JSON для факторного анализа отклонений факта от плана.

## Исходные данные

### Анализ требований

Изучены требования из `agent_stuff/tasks/03_fa_gen_hier_metadata.md`:

1. Каждый узел иерархии — отдельный JSON-объект
2. Каждый показатель имеет `parent` и дочерние элементы (корень без parent, листья без children)
3. Обязательные поля: `id` (int), `code`, `name`
4. Показатель может быть собираем из БД (поле `query`) или вычисляем из потомков
5. Составные показатели: `type` = `sum` | `multi` | `ratio`
6. Для потомков `multi`: `multiplierType` = `rate` | `base`
7. Для `ratio`: указаны `numerator` и `denominator` через ID
8. Показатели типа `multi` обязаны иметь `query` (ставка считается обратным счетом)

### Анализ существующего кода

Изучены классы модуля `libfa2.hier_metadata`:

- **`MetricNode`** (`metric_node.py`): dataclass с полями `id`, `code`, `name`, `parent`, `type`, `query`, `multiplier_type`, `numerator`, `denominator`. Методы `to_dict()` / `from_dict()` для сериализации.
- **`Query`** (`query.py`): dataclass с полем `fields: dict[str, str | list[str]]`. Параметры запроса к БД.
- **`Hierarchy`** (`hierarchy.py`): контейнер для дерева метрик. Плоский dict `metrics: dict[int, MetricNode]`. Методы навигации, валидации, сериализация `to_json()` / `from_json()`.
- **`enums.py`**: `MetricType` (SUM, MULTI, RATIO), `MultiplierType` (RATE, BASE), `ValidationErrorType`.

Формат JSON-сериализации `Hierarchy.to_json()`:
```json
{
  "metrics": [
    {"id": 1, "code": "...", "name": "...", ...}
  ]
}
```

### Анализ общей документации

Изучен раздел 1 документа `agent_stuff/docs/factor_analysis__general_description.md` — общее описание факторного анализа, типы разложения, ключевые понятия.

## Принятые решения

### Формат JSON

Структура JSON принята в соответствии с реализацией `Hierarchy.to_json()`:
- Корневой объект: `{"metrics": [...]}`
- Каждый узел — плоский объект с полями, соответствующими `MetricNode.to_dict()`
- Связи parent-child через поле `parent` (ID родителя)
- Только непустые/ненулевые поля включаются в JSON

### Согласованность с кодом

Имена полей в JSON соответствуют ключам из `MetricNode.to_dict()`:
- `multiplierType` (camelCase, как в `to_dict()`)
- `numerator`, `denominator` (ID числителя/знаменателя)

### Иллюстративные примеры

Сгенерированы 4 примера, покрывающих все типы иерархий:

1. **Пример 1 (sum)** — чисто суммируемая иерархия с вложенными уровнями
2. **Пример 2 (multi)** — мультипликативная иерархия (ставка x объем)
3. **Пример 3 (sum + multi)** — смешанная иерархия из общего описания (ЧПД)
4. **Пример 4 (ratio)** — показатель COR с числителем/знаменателем, каждый из которых имеет свою иерархию (числитель — sum, знаменатель — sum с вложенным multi)
