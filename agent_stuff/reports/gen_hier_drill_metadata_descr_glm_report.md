# Отчет о создании метаданных иерархии показателей

**Дата:** 2026-04-16
**Модель:** glm-4.7
**Задача:** Создать структуру метаданных иерархии показателей для факторного анализа в формате JSON

---

## Обзор задачи

Целью задачи было разработать структуру метаданных для описания иерархии финансовых показателей в формате JSON, основываясь на требованиях из общего описания факторного анализа.

---

## Источник требований

Проанализирован документ `agent_stuff/docs/factor_analysis__general_description.md`, раздел 1 "Разложение по компонентам иерархии".

**Ключевые типы показателей:**
1. **Суммируемые компоненты** — показатель складывается из суммы других показателей
2. **Компоненты-множители** — показатель рассчитывается как произведение множителя на базу
3. **Показатели типа ratio** — показатель рассчитывается как отношение числителя к знаменателю

---

## Разработанная структура JSON

### Основные поля объекта показателя

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `id` | integer | Да | Уникальный идентификатор показателя |
| `code` | string | Да | Код показателя для системного использования |
| `name` | string | Да | Отображаемое название показателя |
| `type` | enum | Нет | Тип показателя: `sum`, `multi`, `ratio` |
| `parent` | integer \| null | Нет | ID родительского показателя. У корня = `null` |
| `query` | object | Условно | Параметры запроса к БД для получения данных |
| `componentMultiPartType` | enum | Условно | Тип компонента-множителя: `rate` или `base` |
| `componentRatioPartType` | enum | Условно | Тип компонента-отношения: `numerator` или `denominator` |

### Общий шаблон

```json
{
  "id": 100,
  "code": "NII",
  "name": "Чистый процентный доход",
  "type": "sum|multi|ratio",
  "parent": null,
  "query": {
    "fieldName1": "value1",
    "fieldName2": ["val1", "val2"]
  },
  "componentMultiPartType": "rate|base",
  "componentRatioPartType": "numerator|denominator"
}
```

## Реализованные типы показателей

### 1. sum (Суммируемые показатели)

- Показатель складывается из суммы своих потомков
- Может иметь поле `query` если его значение хранится в БД (сабтотал)
- Если нет поля `query`, значение вычисляется как сумма потомков

### 2. multi (Компоненты-множители)

- Показатель рассчитывается как произведение множителя на базу
- **Обязательное поле `query`** — данные получаются из БД
- Имеет два дочерних элемента:
  - `rate` — множитель (ставка, процент)
  - `base` — база (объемный показатель)

### 3. ratio (Показатели типа отношение)

- Показатель рассчитывается как отношение двух компонентов (числитель/знаменатель)
- Может использоваться только на верхнем уровне (корневой показатель)
- Имеет два дочерних элемента:
  - `numerator` — числитель
  - `denominator` — знаменатель

## Созданные примеры

### Пример 1: Суммируемые показатели

Демонстрирует иерархию Чистого процентного дохода (ЧПД) с суммируемыми компонентами:
- ЧПД = Процентный доход + Процентный расход + Прочие компоненты

### Пример 2: Показатели типа multi (множители)

Демонстрирует структуру Процентного дохода как произведения ставки на базу:
- Процентный доход = Ставка × Объем требований по долговым фин. инструментам

### Пример 3: Показатель типа ratio (отношение)

Демонстрирует структуру COR (Cost of Risk) как отношения:
- COR = Расходы на резервы / Среднехронологические работающие активы

Пример включает полную иерархию для числителя и знаменателя с суммируемыми компонентами.

### Пример 4: Смешанная иерархия

Демонстрирует полную иерархию ЧПД, включающую все типы показателей:
- Корень: суммируемый показатель (type: sum)
- Второй уровень: компоненты-множители (type: multi)
- Третий уровень: ставки и базы (componentMultiPartType: rate/base)

## Учтенные ограничения и правила

### Правила использования полей

1. **Корневой показатель** — `parent = null`
2. **Листовой элемент** — имеет `query`, без `type`
3. **Показатель типа `multi`** — `type = "multi"`, обязательный `query`
4. **Дочерний элемент `multi`** — обязательно имеет `componentMultiPartType`
5. **Показатель типа `ratio`** — `type = "ratio"`
6. **Дочерний элемент `ratio`** — обязательно имеет `componentRatioPartType`

### Правила получения значений

1. **Если поле `query` указано** — значение получается напрямую из БД по параметрам запроса
2. **Если поле `query` НЕ указано** — значение вычисляется из потомков:
   - `sum`: сумма значений всех потомков
   - `multi`: product(rate) × base
   - `ratio`: numerator / denominator

### Специальные требования

- **Показатели типа `multi` обязательно должны иметь поле `query`**, поскольку один из драйверов (ставка) рассчитывается обратным счетом и не может быть получен простым суммированием

## Сводная таблица типов показателей

| Тип | Описание | Обязательный query | Дочерние элементы |
|-----|----------|-------------------|-------------------|
| `sum` | Суммируемые компоненты | Нет* | Любые показатели |
| `multi` | Множитель × База | Да | 2 элемента: rate + base |
| `ratio` | Числитель / Знаменатель | Нет | 2 элемента: numerator + denominator |
| (отсутствует) | Листовой элемент | Да | Нет |

\* Если query отсутствует, значение вычисляется как сумма потомков
