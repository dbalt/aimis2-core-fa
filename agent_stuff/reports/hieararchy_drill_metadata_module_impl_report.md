# Отчет о реализации модуля иерархии метаданных (hier_metadata)

## Обзор

Выполнена реализация модуля `libfa2.hier_metadata` для управления метаданными иерархической структуры финансовых показателей, используемой в факторном анализе отклонений факта от плана.

## Дата

2026-04-16

## Структура модуля

```
src/libfa2/hier_metadata/
├── __init__.py           # Экспорт публичного API модуля
├── enums.py              # Enum классы для строковых констант
├── query.py              # Класс Query для параметров запросов к БД
├── metric_node.py        # Класс MetricNode для узлов иерархии
└── hierarchy.py          # Класс Hierarchy для управления деревом метрик

tests/libfa2/hier_metadata/
├── __init__.py
└── test_hierarchy_metadata.py  # Комплексные юнит тесты
```

## Реализованные классы

### 1. Enum классы (`enums.py`)

#### `MetricType`
Типы метрик в иерархии:
- `SUM` (`"sum"`) — суммируемые компоненты
- `MULTI` (`"multi"`) — компоненты-множители (произведение rate × base)
- `RATIO` (`"ratio"`) — отношение (числитель / знаменатель), только на корневом уровне

#### `MultiplierType`
Типы компонентов-множителей (потомки узлов типа `multi`):
- `RATE` (`"rate"`) — множитель, нормированный показатель (рассчитывается обратным счетом)
- `BASE` (`"base"`) — база, объемный показатель (берется из БД)

#### `ValidationErrorType`
Типы ошибок валидации:
- `DUPLICATE_METRIC_ID` — дублирование ID метрики
- `DUPLICATE_METRIC_CODE` — дублирование кода метрики
- `MISSING_PARENT_REFERENCE` — ссылка на несуществующего родителя
- `MISSING_NUMERATOR_REFERENCE` — ссылка на несуществующий числитель
- `MISSING_DENOMINATOR_REFERENCE` — ссылка на несуществующий знаменатель
- `INVALID_METRIC_ID` — некорректный ID метрики
- `INVALID_METRIC_CODE` — некорректный код метрики
- `INVALID_METRIC_NAME` — пустое имя метрики
- `INVALID_METRIC_TYPE` — некорректный тип метрики
- `INVALID_MULTIPLIER_TYPE` — некорректный тип множителя
- `INVALID_MULTIPLIER_FOR_NON_MULTI` — множитель указан для не-multi родителя
- `MISSING_QUERY_FOR_MULTI` — отсутствует обязательный query для multi
- `MISSING_NUMERATOR_FOR_RATIO` — отсутствует числитель для ratio
- `MISSING_DENOMINATOR_FOR_RATIO` — отсутствует знаменатель для ratio
- `RATIO_NOT_AT_ROOT` — ratio не на корневом уровне
- `RATIO_HAS_CHILDREN` — ratio имеет дочерние элементы
- `INVALID_QUERY_FIELDS` — некорректные поля в query
- `EMPTY_METRICS` — список метрик пуст
- `CYCLIC_REFERENCE` — циклическая ссылка в иерархии
- `MULTIPLE_ROOTS` — несколько корневых узлов
- `NO_ROOT` — отсутствует корневой узел
- `INCOMPLETE_MULTI_CHILDREN` — неполный набор rate/base для multi
- `DISCONNECTED_SUBTREE` — отключенное поддерево

### 2. Класс Query (`query.py`)

Представляет параметры запроса к базе данных для получения значений плана/факта метрики.

**Атрибуты:**
- `fields: dict[str, str | list[str]] | None` — словарь полей фильтрации

**Ключевые методы:**
- `get_field(name: str) -> str | list[str] | None` — получить значение поля
- `get_field_as_list(name: str) -> list[str]` — получить значение как список
- `is_empty() -> bool` — проверка на отсутствие полей
- `to_dict() -> dict[str, object] | None` — сериализация в словарь (пропускает пустые)
- `from_dict(data: dict[str, object] | None) -> Query` — создание из словаря

**Особенности:**
- Поддержка строковых значений и списков значений
- Автоматическое преобразование числовых и булевых значений в строки при десериализации
- Пропуск `None` значений в списках и пустых словарей
- Валидация: непустые имена полей, непустые значения

### 3. Класс MetricNode (`metric_node.py`)

Представляет отдельный узел в иерархии метрик.

**Атрибуты:**
- `id: int` — уникальный числовой идентификатор (обязательный)
- `code: str` — короткий мнемонический код (обязательный)
- `name: str` — отображаемое имя (обязательное)
- `parent: int | None` — ID родительской метрики
- `type: MetricType | None` — тип составной метрики (sum/multi/ratio)
- `query: Query | None` — параметры запроса к БД
- `multiplier_type: MultiplierType | None` — тип компонента-множителя (rate/base)
- `numerator: int | None` — ID числителя для ratio
- `denominator: int | None` — ID знаменателя для ratio

**Свойства:**
- `is_leaf: bool` — является ли листовым узлом (нет типа)
- `is_root: bool` — является ли корневым узлом (нет родителя)
- `is_composite: bool` — является ли составным узлом (есть тип)
- `is_multi_child: bool` — является ли потомком multi (есть multiplier_type)
- `is_ratio_root: bool` — является ли ratio на корне
- `is_rate_multiplier: bool` — является ли множителем типа rate
- `is_base_multiplier: bool` — является ли множителем типа base

**Методы:**
- `to_dict() -> dict[str, Any]` — сериализация в словарь (пропускает None/пустые)
- `from_dict(data: dict[str, Any]) -> MetricNode` — создание из словаря

**Валидация при инициализации:**
- ID должен быть положительным целым числом
- Код и имя не должны быть пустыми
- Для типа `MULTI` обязательно наличие `query`
- Для типа `MULTI` нельзя указывать `numerator/denominator`
- Для типа `RATIO` обязательно наличие `numerator` и `denominator`
- Для типа `RATIO` нельзя указывать `multiplier_type`

### 4. Класс Hierarchy (`hierarchy.py`)

Управляет деревом метрик для факторного анализа.

**Атрибуты:**
- `metrics: dict[int, MetricNode]` — словарь метрик по ID

**Свойства:**
- `metric_ids: set[int]` — множество всех ID метрик
- `metric_codes: set[str]` — множество всех кодов метрик
- `roots: list[MetricNode]` — список корневых узлов (parent = None)
- `leaves: list[MetricNode]` — список листовых узлов (без потомков)

**Методы навигации:**
- `get_metric(metric_id: int) -> MetricNode | None` — получить по ID
- `get_metric_by_code(code: str) -> MetricNode | None` — получить по коду
- `get_children(metric_id: int) -> list[MetricNode]` — прямые потомки
- `get_parent(metric_id: int) -> MetricNode | None` — родитель
- `get_ancestors(metric_id: int) -> list[MetricNode]` — все предки
- `get_descendants(metric_id: int) -> list[MetricNode]` — все потомки
- `get_path_to_root(metric_id: int) -> list[MetricNode]` — путь до корня
- `get_depth(metric_id: int) -> int` — глубина узла (0 для корня)
- `get_max_depth() -> int` — максимальная глубина иерархии
- `is_ancestor_of(ancestor_id: int, descendant_id: int) -> bool` — проверка предка

**Методы управления:**
- `add_metric(metric: MetricNode) -> None` — добавить метрику
- `add_metrics(metrics: Iterable[MetricNode]) -> None` — добавить несколько метрик
- `remove_metric(metric_id: int) -> None` — удалить метрику

**Методы сериализации:**
- `to_json(indent: int | None = 2) -> str` — сериализация в JSON
- `from_json(json_str: str) -> Hierarchy` — десериализация из JSON

**Методы валидации:**
- `validate() -> ValidationReport` — валидация иерархии

**Вспомогательные классы:**
- `ValidationError` — представляет ошибку валидации
- `ValidationReport` — результат валидации (`is_valid`, список ошибок)

## Особенности реализации

### 1. Сериализация/десериализация JSON

- **Пустые/None поля пропускаются** в JSON выходе (согласно требованиям)
- `Query.to_dict()` возвращает `None` если query пустой
- `MetricNode.to_dict()` опускает поля с `None` значениями
- Поддержка форматов с и без отступов (compact JSON)
- Корректная обработка Unicode символов (русский текст)

### 2. Валидация

Реализована комплексная валидация структуры иерархии:

**Проверки целостности:**
- Пустой список метрик
- Несколько корней (или none)
- Дублирование ID и кодов метрик
- Циклические ссылки (DFS алгоритм)
- Отключенные поддеревья

**Проверки ссылок:**
- Существование родительской метрики
- Существование числителя/знаменателя для ratio

**Проверки типов:**
- Корректность типа метрики (sum/multi/ratio)
- Корректность типа множителя (rate/base)
- Обязательный `query` для `multi` метрик
- Обязательные `numerator` и `denominator` для `ratio` метрик
- `multiplier_type` только для потомков `multi`

**Особенности ratio иерархий:**
- Допускается несколько корней для ratio структуры
- (ratio root + numerator root + denominator root)
- Ratio не может иметь потомков
- Ratio должен быть на корневом уровне

### 3. Навигация по иерархии

Реализованы методы для навигации по дереву:
- Поиск детей, родителей, предков, потомков
- Определение глубины узла
- Проверка отношений предок-потомок
- Получение пути до корня
