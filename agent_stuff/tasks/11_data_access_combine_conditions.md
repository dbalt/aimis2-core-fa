Задача доработать модуль libfa2.data_access (@src/libfa2/data_access/)



1. Нужно определить класс ConditionSet, который по смыслу будет типизированной версией словаря Dict[str, Any|List[Any]], в котором ключи - имена столбцов, а значения соответствующие этим ключам как раз фильтруемые значения в таблице. Если есть словарь вида 
```
{
    "name": ["foo", "bar"],
    "part_id": 1
}
```
То он подразумевает использование в sql запросе в секции where вот так:
where 1=1
    ...
    and name in ('foo', 'bar')
    and part_id = 1


обязательно должны быть следующие методы:
```
@property
columns()->List[str]:  # какие столбцы есть в ConditionSet

get_filter_for_column(column_name:str)-> Any|List[Any]: # Собственно перечень значений для фильтрации, или просто значение
```

также должен быть метод ```to_dict()```, и у класса фабричный метод ```from_dict(dict:Dict[str,Any|List[Any]])```

Остальные методы додумай сам (в том числе методы для модификации содержимого - CRUD операции)





2. Нужно определить класс ConditionOr - контейнер для ConditionSet-ов (или для других ConditionOr, или ConditionAnd), означает что каждый из ConditionSet-ов нужно применить через OR (логическое `ИЛИ`)

То есть, если у нас ConditionOr состоит из двух ConditionSet для примера таких: 
```
{
    "name": ["foo", "bar"],
    "part_id": 1
}
и
{
    "name": "baz",
    "part_id": [1,2,3]
}
```
То такой ConditionOr применяется в sql запросе так:
```
where 1=1
    and (
        name in ('foo', 'bar') and part_id = 1
        or name = 'baz' and part_id in (1,2,3)
    )
```
Нужно реализовать стандартный набор методов + CRUD.



3. ConditionAnd - то же самое что ConditionOr, только для `AND` (логическое `И`)



Вообще говоря, эти три класса должны иметь общий супер класс ConditionBase. И ConditionOr/ConditionAnd - это контейнеры для элементов типа ConditionBase. 
 





4. нужно реализовать функцию 
```
def reduce_condition(condition:ConditionBase) -> ConditionBase
``` 

Логика такая:
- Один ConditionSet возвращается as is

- ConditionAnd(ConditionSet1, ConditionSet2) превращается в один ConditionSet, путем добавления столбцов (с их фильтрами) из второго в первый. Если есть пересечение по именам столбцов - то в результирующий condition set для пересекающихся столбцов попадают только те значения фильтров, которые есть и в 1 и в 2. Если общих значений фильтров нет - то это ошибка.

- ConditionOr(ConditionSet1, ConditionSet2) может быть средуцирован, если в обоих сетах одинаковые столбцы. В результате получается ConditionSet в котором значения фильтров объеденены.

- Любые остальные конфигурации не могут быть средуцированы

- Если в ConditionOr или в ConditionAnd больше чем 2 составляющих, то нужно пытаться средуцировать каждый с каждым. После каждого удачного редуцирования начинать этот процесс сначала. Останавливаться только когда попытались каждый с каждым, и никакой редукции не случилось. 

- Также reduce нужно делать начиная с листьев. То есть при конфигурации ConditionAnd(ConditionOr1, ConditionOr2, ConditionSet) нужно сначала средуцировать содержимое ConditionOr1, затем ConditionOr2 и тд
