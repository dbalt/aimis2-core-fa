Нужно имплементировать микросервис факторного анализа

Заготовка под сервер - в файле @src/libfa2/fa_server.py

Нужно дополнить имплементацию метода m__process_request

`request_payload` который приходит на вход, это словарь который состоит из двух полей 
```
{
    "action": "<some_action>,
    "payload": {... some payload ...}
}
```

в результате отработки тело метода нужно либо вернуть какой то полезный результат, либо выбросить исключение. Вообще метод подразумевает возможность возвращать множественный результат, но в рамках текущего сервиса возврат будет только один

Для каждого action мы делаем ветку if, в которой происходит какая то обработка. После чего делается возврат результата через yield и сразу же return (ну или выброс исключения, если возникла ошибка)

Если пришел запрос с неподдерживаемым action (то есть мы пропустили все if ветки) - то в конце должно быть выкинуто исключение

Ожидаемое поведение в зависимости от action-а:

### 1. Саммари по отклонению
action === 'get_deviation_summary' 
структура payload: 
```
{
    "code": "some_code",
    "dt": "some_date_in_iso_format"
}
```
Алгоритм:
1. Запрашиваем результаты по коду и дате (get_results(...) из DataMgmt. Нужно добавить в конструктор инстанс DataMgmt). Если есть - то возвращаем саммари и выходим 

2. Если данных нет, то запрашиваем метаданные по коду (get_metadata(...)). Если их нет (вернулся Res.err), то выбрасываем исключение

3. метаданные это по факту экземпляр класса DeviationCalcParams но с пустым rep_dt. Десериализируем этот dict в DeviationCalcParams, в поле rep_dt проставляем dt из payload, и вызываем calculate_deviations из libfa2.fa_impl.calc

4. Если на предыдущем шаге ОК - то собираем из результата фактуру по отклонениям в формате json dict (collect_for_summary из libfa2.fa_impl.collect) - это будет то самое data для таблички ***__results

5. Если на предыдущем шаге ОК - то собираем саммари по этой фактуре (summarize из libfa2.fa_impl.summarize)

6. Если ОК, то пробуем сохранить data (шаг4) и саммари (шаг5) в БД (метод save_results из DataMgmt)

7. Независимо от успеха или провала шага 6, возвращаем саммари (шаг 5) и выходим
