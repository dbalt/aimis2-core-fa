# Метаданные алгоритмов разложения по аналитическим разрезам

## Описание

Метаданные описывают алгоритмы разворота (дрейлинга) значений показателей по аналитическим разрезам. Каждый алгоритм определяет порядок последовательной детализации данных от общего итога до наиболее детального уровня.

### Основные концепции

- **Порядок разложения** — последовательность шагов детализации данных
- **Аналитический разрез** — измерение для детализации данных (сегмент, геоструктура, продукт, канал и т.д.)
- **Шаг разложения** — уровень детализации, на котором может быть задействован один или несколько аналитических разрезов одновременно (например, пересечение сегмента + продукта)
- **Рекурсивное разложение** — сначала по первому шагу, затем каждый результат — по второму, и т.д.
- **Ограничение** — драйверы не могут быть отдельно разложены по аналитическим разрезам, только вместе с верхнеуровневым показателем

## Структура JSON

### Корневой элемент

```json
{
  "algorithms": [...],
  "dimensions": [...]
}
```

### Объект алгоритма разложения

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `id` | int | Да | Уникальный числовой идентификатор алгоритма |
| `drill_order` | array | Да | Порядок разложения — массив шагов, где каждый шаг — это массив кодов аналитических разрезов |

### Объект аналитического разреза

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `code` | string | Да | Код аналитического разреза (используется как ссылка из `drill_order`) |
| `name` | string | Да | Отображаемое имя разреза |
| `column` | string | Да | Наименование столбца в таблице БД, содержащего значения данного разреза |

## Полная схема JSON

```json
{
  "algorithms": [
    {
      "id": 1,                           // Уникальный числовой идентификатор
      "drill_order": [                   // Массив шагов разложения
        ["code"],                        // Шаг 1: один разрез
        ["code1", "code2"],              // Шаг 2: несколько разрезов (пересечение)
        ...
      ]
    }
  ],
  "dimensions": [
    {
      "code": "string",                  // Код разреза для ссылок
      "name": "string",                  // Отображаемое имя
      "column": "string"                 // Столбец в БД
    }
  ]
}
```

## Пояснение к примеру

### Алгоритм 1 (id: 1) — Последовательное разложение
- **Шаг 1:** Сегмент
- **Шаг 2:** Геоструктура
- **Шаг 3:** Продукт

**Процесс разложения:**
1. Уровень 0: общий итог по всем данным
2. Уровень 1: разбивка по сегментам (Юридические лица, Физические лица, Прочие)
3. Уровень 2: для каждого сегмента — разбивка по геоструктуре
4. Уровень 3: для каждой комбинации сегмент + геоструктура — разбивка по продуктам

### Алгоритм 2 (id: 2) — Альтернативный порядок
- **Шаг 1:** Геоструктура
- **Шаг 2:** Сегмент
- **Шаг 3:** Канал продаж

### Алгоритм 3 (id: 3) — С пересечением разрезов
- **Шаг 1:** Сегмент
- **Шаг 2:** Геоструктура + Продукт (одновременно, пересечение)
- **Шаг 3:** Канал продаж

На втором шаге данные группируются сразу по двум измерениям — геоструктуре и продукту вместе.

### Алгоритм 4 (id: 4) — С пересечением на первом шаге
- **Шаг 1:** Сегмент + Продукт
- **Шаг 2:** Геоструктура

Сразу на первом уровне происходит детализация по пересечению сегмента и продукта.

### Алгоритм 5 (id: 5) — Одноуровневое разложение
- **Шаг 1:** Сегмент

Разложение только на один уровень — без дальнейшей детализации.

## Использование метаданных

### Пример SQL-запроса для разложения (один разрез)

Для разложения показателя по первому шагу алгоритма 1:

```sql
-- Получение значений плана и факта по сегментам
SELECT
    segment_id as dimension_value,
    segment_name as dimension_name,
    SUM(plan_value) as plan,
    SUM(fact_value) as fact,
    SUM(fact_value) - SUM(plan_value) as deviation
FROM indicator_data
WHERE indicator_id = 'commission_income'
  AND report_date = '2026-04-01'
GROUP BY segment_id, segment_name
```

### Пример SQL-запроса с пересечением разрезов

Для разложения по пересечению геоструктуры и продукта (алгоритм 3, шаг 2):

```sql
-- Получение значений плана и факта по пересечению геоструктуры и продукта
SELECT
    geo_structure_id as geo_value,
    geo_structure_name as geo_name,
    product_id as product_value,
    product_name as product_name,
    SUM(plan_value) as plan,
    SUM(fact_value) as fact,
    SUM(fact_value) - SUM(plan_value) as deviation
FROM indicator_data
WHERE indicator_id = 'commission_income'
  AND report_date = '2026-04-01'
  AND segment_id = 'UL'  -- Фильтрация по значению предыдущего шага
GROUP BY geo_structure_id, geo_structure_name, product_id, product_name
```

### Рекурсивное разложение

Алгоритм разложения выполняется пошагово:

1. **Шаг N:** выполнение запроса для текущего уровня с фильтрацией по значениям предыдущих шагов
2. **Результат:** набор записей с агрегированными значениями по заданным разрезам
3. **Следующий шаг:** повтор для каждой полученной записи (если есть следующие шаги в `drill_order`)

---

## Примечания

1. **Универсальность** — алгоритмы не привязаны к конкретным показателям и могут применяться к любым показателям
2. **Пересечение разрезов** — на одном шаге может быть несколько разрезов, что позволяет получать детализацию по их пересечению
3. **Иерархия** — порядок шагов разложения определяет иерархию результатов
4. **Атомарность** — на каждом шаге разложения получается самодостаточный набор данных
5. **Кодовая ссылка** — `drill_order` использует `code` из массива `dimensions`
6. **Гибкость** — структура позволяет легко добавлять новые разрезы и алгоритмы без изменения кода приложения
