# Метаданные иерархии показателей для факторного анализа

## Назначение

Документ описывает формат хранения метаданных об иерархической структуре финансовых показателей, используемой для факторного анализа отклонений факта от плана.

---

## Общая структура

Метаданные представляют собой JSON-структуру, описывающую древовидную иерархию показателей. Каждый узел может быть:

- **Листом** — показатель, который можно получить напрямую из БД
- **Составным узлом** — показатель, который рассчитывается из дочерних компонентов

---

## Схема объекта показателя

```json
{
  "id": "int",              // Уникальный идентификатор показателя
  "code": "string",         // Короткий код показателя для использования в API/UI
  "name": "string",         // Отображаемое имя показателя
  "parent": "int|null",     // ID родительского показателя (null для корня)
  "type": "sum|multi|ratio", // Тип для составных показателей (обязательно для не-листьев)
  "query": { ... },         // Параметры запроса к БД (для собираемых показателей)
  "multiplierType": "rate|base" // Тип компонента-множителя (для дочерних элементов типа multi)
}
```

### Описание полей

| Поле | Обязательное | Тип | Описание |
|------|-------------|-----|----------|
| `id` | Да | int | Уникальный числовой идентификатор показателя |
| `code` | Да | string | Короткий мнемонический код для использования в системе |
| `name` | Да | string | Отображаемое название показателя (человеко-читаемое) |
| `parent` | Нет | int/null | ID родительского показателя (null для корня) |
| `type` | Для не-листьев | enum(`sum`, `multi`, `ratio`) | Тип составного показателя |
| `query` | Обязательно для `type: multi` и `ratio`, опционально для `type: sum` и листов | object | Фильтры для запроса значений плана/факта |
| `multiplierType` | Для потомков `multi` | enum(`rate`, `base`) | Тип компонента-множителя: множитель или база |
| `numerator` | Для `type: ratio` | int | ID компонента-числителя |
| `denominator` | Для `type: ratio` | int | ID компонента-знаменателя |

---

## Типы показателей

### 1. Листовой показатель (собираемый из БД)

Показатель, для которого есть данные в БД. Указывается свойство `query` с параметрами выборки.

```json
{
  "id": 1001,
  "code": "INT_INC",
  "name": "Процентный доход",
  "parent": 900,
  "query": {
    "segment": "corporate",
    "product": "loans"
  }
}
```

### 2. Составной показатель типа `sum` (суммируемые компоненты)

Показатель, равный сумме своих дочерних элементов.

- **Без `query`** — значение рассчитывается как сумма дочерних элементов
- **С `query`** — значение берется из БД (если сабтоталы хранятся в БД, данные из БД имеют приоритет)

```json
{
  "id": 900,
  "code": "NII",
  "name": "Чистый процентный доход",
  "parent": 100,
  "type": "sum"
}

// Или, если сабтотал хранится в БД:
{
  "id": 900,
  "code": "NII",
  "name": "Чистый процентный доход",
  "parent": 100,
  "type": "sum",
  "query": {
    "metric": "nii_total"
  }
}
```

### 3. Составной показатель типа `multi` (компоненты-множители)

Показатель, равный произведению компонентов-множителей (множителя на базу).

> **Важно:** Показатели типа `multi` **ОБЯЗАНЫ** иметь поле `query`. Это связано с тем, что один из компонентов-множителей (ставка, `rate`) рассчитывается обратным счетом: `rate = показатель / base`.

```json
{
  "id": 101,
  "code": "INT_INC",
  "name": "Процентный доход",
  "parent": 10,
  "type": "multi",
  "query": {
    "metric": "interest_income"
  }
}
```

### 4. Составной показатель типа `ratio` (отношение)

Показатель, рассчитываемый как отношение двух компонентов:

```
ratio = Компонент-числитель / Компонент-знаменатель
```

**Характеристики:**

- Допускается **только на верхнем уровне** (корневой показатель)
- Числитель и знаменатель могут быть показателями типа `sum` или `multi` с собственной иерархией
- **Обязательно** имеют поля `numerator` и `denominator` — ссылки на компоненты-числитель и компонент-знаменатель

```json
{
  "id": 5,
  "code": "COR",
  "name": "Cost of Risk",
  "parent": null,
  "type": "ratio",
  "numerator": 501,    // ID показателя "Расходы на резервы"
  "denominator": 502    // ID показателя "Среднехронологические работающие активы"
}
```

> **Примечание:** Для показателей типа `ratio` поле `query` обычно не требуется, так как значение рассчитывается как отношение числителя к знаменателю. Однако если значение ratio хранится в БД отдельно, поле `query` может быть указано.

---

## Формат свойства `query`

Свойство `query` описывает параметры фильтрации для получения плановых и фактических значений показателя из БД.

```json
{
  "query": {
    "fieldName": "fieldValue",           // Пример: { "segment": "corporate" }
    "anotherField": ["val1", "val2"]     // Или массив значений
  }
}
```

### Правила использования `query`:

| Тип показателя | Наличие `query` | Правило |
|----------------|-----------------|---------|
| Лист | Опционально | Отсутствует → рассчитывается как сумма потомков |
| `type: sum` | Опционально | Присутствует → сабтотал хранится в БД (приоритет) |
| `type: multi` | **Обязательно** | Требуется для обратного расчета множителя |
| `type: ratio` | Опционально | Обычно отсутствует (рассчитывается как отношение), но может быть указано, если значение хранится в БД |

> Если показатель не собираем из БД напрямую (например, рассчитывается как сумма потомков или отношение числителя к знаменателю), поле `query` отсутствует. Обычно сабтоталы не хранятся на всех уровнях иерархии, но если они есть — значения из БД имеют приоритет над расчетными.

---

## Типы компонентов-множителей

| Тип | Описание | Пример |
|-----|----------|--------|
| `rate` | Множитель — нормированный показатель (ставка, процент) | Ставка по кредитам, процентная маржа |
| `base` | База — объемный показатель, абсолютное значение | Объем выданных кредитов, количество клиентов |

---

## Обратный расчет множителя для компонентов-множителей

Для показателей типа `multi` с компонентом-множителем типа `rate` используется **обратный расчет**:

```
rate = multi_показатель / base
```

**Почему это важно:**

- Значение `multi`-показателя (процентный доход, расход и т.д.) берется из БД (через `query`)
- Значение `base`-компонента (объем) берется из БД (через `query`)
- Значение `rate`-компонента (множитель) **рассчитывается** как отношение двух значений из БД

Именно поэтому показатели типа `multi` **обязаны** иметь поле `query` — необходимо знать итоговое значение для корректного расчета множителя обратным счетом.

**Пример расчета:**

| Показатель | План | Факт | Отклонение |
|------------|------|------|------------|
| Процентный доход (`multi`) | 1000 | 750 | -250 |
| ├── Ставка (`rate`, расчетная) | 0,0200 | 0,01875 | -0,00125 |
| └── Объем (`base`) | 50 000 | 40 000 | -10 000 |

Расчет ставки:
- План: `rate = 1000 / 50 000 = 0,0200` (2,00%)
- Факт: `rate = 750 / 40 000 = 0,01875` (1,875%)

## Работа с плоской структурой

Поскольку каждый показатель хранится в отдельном JSON-объекте, а иерархия строится через поле `parent`, при работе с метаданными необходимо:

1. **Нахождение потомков узла** — фильтрация массива показателей по условию `parent === node.id`
2. **Нахождение родителя узла** — поиск показателя с `id === node.parent`
3. **Построение дерева** — рекурсивное построение структуры, начиная от корня (`parent === null`)

Пример поиска потомков на JavaScript:
```javascript
function getChildren(nodeId, allMetrics) {
  return allMetrics.filter(m => m.parent === nodeId);
}

function buildTree(allMetrics) {
  const root = allMetrics.find(m => m.parent === null);
  function addChildren(node) {
    node.children = getChildren(node.id, allMetrics);
    node.children.forEach(addChildren);
  }
  addChildren(root);
  return root;
}
```

## Правила валидации

1. **Корень** — имеет `parent: null`, является составным показателем (имеет потомков через ссылку `id` в их поле `parent`)
2. **Лист** — узел, на который никто не ссылается как на родителя. Если не имеет `query`, его значение рассчитывается как сумма потомков
3. **Суммируемый узел** (`type: "sum"`) — дочерние элементы (на которые он ссылается через свой `id` в их `parent`) не обязательно имеют `multiplierType`. Если имеет `query`, значение берется из БД, иначе — сумма потомков
4. **Узел типа multi** (`type: "multi"`) — все дочерние элементы должны иметь `multiplierType` (`rate` или `base`). **Обязательно** имеет `query` (требуется для обратного расчета множителя)
5. **Узел типа ratio** (`type: "ratio"`) — может быть только на верхнем уровне (корневой показатель). **Обязательно** имеет поля `numerator` и `denominator` — ссылки на существующие показатели, которые могут иметь свою иерархию
6. **Уникальность** — все `id` (int) и `code` (string) должны быть уникальны в рамках всей иерархии
7. **Собираемость** — если узел не имеет `query`, его значение рассчитывается как сумма дочерних (`type: "sum"`), произведение (`type: "multi"`) или отношение (`type: "ratio"`). При наличии `query` значение из БД имеет приоритет
8. **Целостность ссылок** — для каждого узла с `parent` должен существовать узел с соответствующим `id`. Для узлов типа `ratio` должны существовать узлы с `id`, указанными в `numerator` и `denominator`
