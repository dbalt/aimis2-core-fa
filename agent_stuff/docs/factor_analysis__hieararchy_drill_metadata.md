## Общее описание

Метаданные иерархии показателей описывают структуру финансовых показателей для факторного анализа. Каждый показатель хранится в базе данных и имеет свою иерархию, аналитические разрезы и значения плана и факта.

**Хранилище:** Все показатели (независимо от их иерархии) хранятся в одной таблице БД.

---

## Структура JSON

### Общий шаблон объекта показателя

```json
{
  "id": 100,
  "code": "NII",
  "name": "Чистый процентный доход",
  "type": "sum|multi|ratio",
  "parent": null,
  "query": {
    "fieldName1": "value1",
    "fieldName2": ["val1", "val2"]
  },
  "componentMultiPartType": "rate|base",
  "componentRatioPartType": "numerator|denominator"
}
```

### Описание полей

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| **id** | integer | Да | Уникальный идентификатор показателя |
| **code** | string | Да | Код показателя для системного использования |
| **name** | string | Да | Отображаемое название показателя |
| **type** | enum | Нет | Тип показателя: `sum`, `multi`, `ratio` |
| **parent** | integer \| null | Нет | ID родительского показателя. У корня = `null` |
| **query** | object | Нет* | Параметры запроса к БД для получения данных |
| **componentMultiPartType** | enum | Нет** | Тип компонента-множителя: `rate` или `base` |
| **componentRatioPartType** | enum | Нет*** | Тип компонента-отношения: `numerator` или `denominator` |

\* Обязательно для показателей типа `multi` и для листьев иерархии, их данные должны быть получены напрямую из БД. Может быть также определен для других уровней иерархии, чтобы упростить запрос данных

\** Обязательно для дочерних элементов показателя типа `multi`

\*** Обязательно для дочерних элементов показателя типа `ratio`

## Типы показателей

### 1. sum (Суммируемые показатели)

Показатель складывается из суммы своих потомков.

```json
{
  "id": 100,
  "code": "NII",
  "name": "Чистый процентный доход",
  "type": "sum",
  "parent": null
}
```

**Характеристики:**
- Может иметь поле `query` если его значение хранится в БД (сабтотал)
- Если нет поля `query`, значение вычисляется как сумма потомков

### 2. multi (Компоненты-множители)

Показатель рассчитывается как произведение множителя на базу.

```json
{
  "id": 201,
  "code": "INT_INC",
  "name": "Процентный доход",
  "type": "multi",
  "parent": 100
}
```

**Характеристики:**
- **Обязательное поле `query`** — данные получаются из БД
- Имеет два дочерних элемента с `componentMultiPartType`:
  - `rate` — множитель (ставка, процент)
  - `base` — база (объемный показатель)
- Элемент с типом `rate` рассчитывается обратным счетом. `base` и `parent` должеы быть собираемыми из БД

### 3. ratio (Показатели типа отношение)

Показатель рассчитывается как отношение двух компонентов (числитель/знаменатель).

```json
{
  "id": 300,
  "code": "COR",
  "name": "Cost of Risk",
  "type": "ratio",
  "parent": null
}
```

**Характеристики:**
- Может использоваться только на верхнем уровне (корневой показатель)
- Имеет два дочерних элемента с `componentRatioPartType`:
  - `numerator` — числитель
  - `denominator` — знаменатель

## Правила формирования иерархии

### Связи parent - children

```
┌──────────────────────────────────────────────┐
│ Корневой показатель (parent = null)          │
│   type: sum | multi | ratio                  │
└────────────┬─────────────────────────────────┘
             │
             ├── Дочерний 1 (parent = id_корня)
             │   type: sum | multi
             │
             ├── Дочерний 2 (parent = id_корня)
             │   type: sum | multi
             │
             └── Листовой элемент (parent = id_родителя)
                 type: не указано (лист)
                 query: { ... }
```

### Условия использования полей

| Условие | Обязательные поля |
|---------|-------------------|
| Корневой показатель | `parent = null` |
| Листовой элемент | `query`, нет `type` |
| Показатель типа `multi` | `type = "multi"`, `query` |
| Дочерний элемент `multi` | `componentMultiPartType` |
| Показатель типа `ratio` | `type = "ratio"` |
| Дочерний элемент `ratio` | `componentRatioPartType` |

### Правила получения значений

1. **Если поле `query` указано** — значение получается напрямую из БД по параметрам запроса
2. **Если поле `query` НЕ указано** — значение вычисляется из потомков:
   - `sum`: сумма значений всех потомков
   - `multi`: product(rate) × base
   - `ratio`: numerator / denominator

> **Важно:** Показатели типа `multi` обязательно должны иметь поле `query`, поскольку один из драйверов (ставка) рассчитывается обратным счетом и не может быть получен простым суммированием.

## Примеры

### Пример 1: Суммируемые показатели

**Сценарий:** Чистый процентный доход = Процентный доход + Процентный расход + Прочие компоненты

```json
[
  {
    "id": 100,
    "code": "NII",
    "name": "Чистый процентный доход",
    "type": "sum",
    "parent": null
  },
  {
    "id": 101,
    "code": "INT_INC",
    "name": "Процентный доход",
    "type": "multi",
    "parent": 100,
    "query": {
      "metricType": "interest_income"
    }
  },
  {
    "id": 102,
    "code": "INT_EXP",
    "name": "Процентный расход",
    "type": "multi",
    "parent": 102,
    "query": {
      "metricType": "interest_expense"
    }
  },
  {
    "id": 103,
    "code": "NII_OTHER",
    "name": "Прочие компоненты, включенные в ЧПД",
    "type": "sum",
    "parent": 100
  },
  {
    "id": 10301,
    "code": "NII_OTHER_1",
    "name": "Компонент 1",
    "parent": 103,
    "query": {
      "metricType": "nii_other",
      "component": 1
    }
  },
  {
    "id": 10302,
    "code": "NII_OTHER_2",
    "name": "Компонент 2",
    "parent": 103,
    "query": {
      "metricType": "nii_other",
      "component": 2
    }
  }
]
```

**Визуальная структура:**

```
NII (id: 100)
├── INT_INC (id: 101)
│   ├── Ставка процентного дохода
│   └── Объем требований по долговым фин. инструментам
│
├── INT_EXP (id: 102)
│   ├── Ставка процентного расхода
│   └── Объем обязательств по долговым фин. инструментам
│
└── NII_OTHER (id: 103)
    ├── NII_OTHER_1 (id: 10301)
    └── NII_OTHER_2 (id: 10302)
```

### Пример 2: Показатели типа multi (множители)

**Сценарий:** Процентный доход = Ставка × Объем

```json
[
  {
    "id": 101,
    "code": "INT_INC",
    "name": "Процентный доход",
    "type": "multi",
    "parent": 100,
    "query": {
      "metricType": "interest_income"
    }
  },
  {
    "id": 10101,
    "code": "INT_INC_RATE",
    "name": "Ставка процентного дохода",
    "parent": 101,
    "componentMultiPartType": "rate",
    "query": {
      "metricType": "interest_income",
      "component": "rate"
    }
  },
  {
    "id": 10102,
    "code": "INT_INC_BASE",
    "name": "Объем требований по долговым фин. инструментам",
    "parent": 101,
    "componentMultiPartType": "base",
    "query": {
      "metricType": "interest_income",
      "component": "base"
    }
  }
]
```

**Визуальная структура:**

```
INT_INC (id: 101)
├── Ставка процентного дохода (id: 10101, rate)
└── Объем требований по долговым фин. инструментам (id: 10102, base)
```

**Правило расчета:**
- `INT_INC_значение = INT_INC_RATE_значение × INT_INC_BASE_значение`

## Сводная таблица типов

| Тип | Описание | Обязательный query | Дочерние элементы |
|-----|----------|-------------------|-------------------|
| `sum` | Суммируемые компоненты | Нет* | Любые показатели |
| `multi` | Множитель × База | Да | 2 элемента: rate + base |
| `ratio` | Числитель / Знаменатель | Нет | 2 элемента: numerator + denominator |
| (отсутствует) | Листовой элемент | Да | Нет |

\* Если query отсутствует, значение вычисляется как сумма потомков
